Processes — Lesson 01

Child Processes Overview

Run shell commands, execute scripts, and offload work — all without blocking your server.

Why Child Processes?

Node.js is single-threaded. But sometimes you need to:

  • Run system commands — git status, ffmpeg, docker build
  • Execute other languages — Python scripts, shell scripts, Go binaries
  • Isolate crash-prone code — if it crashes, your main process survives
  • Use all CPU cores — one process per core for compute-heavy work

The node:child_process module spawns new OS processes. Each child process has its own memory, its own V8 instance (if Node), and communicates with the parent via IPC (Inter-Process Communication) or stdio streams.

The Four Methods

MethodWhen to UseOutputShell?
exec(cmd) Short commands, small output (<1MB) Buffered (entire stdout/stderr as string) Yes
execFile(file, args) Run a specific binary without a shell Buffered No (safer)
spawn(cmd, args) Long-running, large output (streaming) Streams (stdout/stderr as Readable) No (optional)
fork(modulePath) Run another Node.js script with IPC channel IPC messages + stdio No

exec — Quick Shell Commands

import { exec } from 'node:child_process';
import { promisify } from 'node:util';

const execAsync = promisify(exec);

try {
  const { stdout, stderr } = await execAsync('git log --oneline -5');
  console.log(stdout);
  if (stderr) console.error('stderr:', stderr);
} catch (err) {
  console.error('Command failed:', err.message);
  console.error('Exit code:', err.code);
}
Security: exec runs in a shell. Never pass user input directly: exec(`ls ${userInput}`) is a command injection vulnerability. Use execFile or spawn with args array for untrusted input.

spawn — Streaming Output

For long-running processes or large output, spawn gives you streams:

import { spawn } from 'node:child_process';

const child = spawn('find', ['.', '-name', '*.js']);

child.stdout.on('data', (chunk) => {
  console.log('Found:', chunk.toString());
});

child.stderr.on('data', (chunk) => {
  console.error('Error:', chunk.toString());
});

child.on('close', (code) => {
  console.log(`Process exited with code ${code}`);
});

child.stdout and child.stderr are Readable streams — everything from your fs/streams lessons applies. You can pipe, transform, or collect chunks.

fork — Node.js-to-Node.js Communication

fork() is specialized for running another Node.js script. It automatically creates an IPC channel for message passing: 

// parent.js
import { fork } from 'node:child_process';

const child = fork('./worker.js');

child.send({ task: 'processData', data: [1, 2, 3] });

child.on('message', (result) => {
  console.log('Result from child:', result);
});

// worker.js
process.on('message', (msg) => {
  const result = msg.data.map(x => x * 2);
  process.send({ result });
});
