Processes — Lesson 02

Worker Threads

Run CPU-intensive JavaScript in parallel without spawning a new OS process.

Worker Threads vs Child Processes

AspectChild ProcessWorker Thread
IsolationSeparate OS process, own memorySame process, shared memory possible
Startup costHeavy (~30ms+ to spawn)Lighter (~5ms to create)
CommunicationIPC (serialized messages) or stdioMessages + SharedArrayBuffer
Can runAny language/binaryOnly JavaScript/WASM
Crash behaviorChild crashes, parent survivesWorker crash can be caught by parent
Use forExternal programs, shell commands, isolationCPU-bound JS: parsing, crypto, image processing
Rule of thumb: Use Worker Threads when you need to run JavaScript/TypeScript that's CPU-heavy. Use Child Processes when you need to run external programs or need full process isolation.

Basic Worker Thread Pattern

// main.js
import { Worker } from 'node:worker_threads';

function runWorker(data) {
  return new Promise((resolve, reject) => {
    const worker = new Worker('./heavy-task.js', {
      workerData: data,
    });

    worker.on('message', resolve);
    worker.on('error', reject);
    worker.on('exit', (code) => {
      if (code !== 0) {
        reject(new Error(`Worker exited with code ${code}`));
      }
    });
  });
}

// Use it in your HTTP handler without blocking:
const result = await runWorker({ numbers: [1, 2, 3, 4, 5] });
console.log(result);
// heavy-task.js
import { parentPort, workerData } from 'node:worker_threads';

// This runs on a SEPARATE thread — doesn't block the event loop
function heavyComputation(numbers) {
  // Simulate CPU-intensive work
  let sum = 0;
  for (let i = 0; i < 1_000_000_000; i++) {
    sum += numbers[i % numbers.length];
  }
  return sum;
}

const result = heavyComputation(workerData.numbers);
parentPort.postMessage(result);

Inline Workers (No Separate File)

For small tasks, create a worker from inline code:

import { Worker } from 'node:worker_threads';

function runInline(fn, data) {
  return new Promise((resolve, reject) => {
    const worker = new Worker(
      `
      const { parentPort, workerData } = require('worker_threads');
      const fn = ${fn.toString()};
      const result = fn(workerData);
      parentPort.postMessage(result);
      `,
      { eval: true, workerData: data }
    );
    worker.on('message', resolve);
    worker.on('error', reject);
  });
}

const result = await runInline(
  (data) => data.reduce((a, b) => a + b, 0),
  [1, 2, 3, 4, 5]
);
console.log(result); // 15

SharedArrayBuffer — True Shared Memory

Workers can share memory with the main thread for zero-copy data passing:

// main.js
import { Worker } from 'node:worker_threads';

const sharedBuffer = new SharedArrayBuffer(4); // 4 bytes
const view = new Int32Array(sharedBuffer);
view[0] = 0; // initial counter value

const worker = new Worker('./counter-worker.js', {
  workerData: { sharedBuffer },
});

// Both main thread and worker see the same memory
setTimeout(() => {
  console.log('Counter from main:', view[0]); // modified by worker!
}, 1000);

// counter-worker.js
import { workerData } from 'node:worker_threads';
const view = new Int32Array(workerData.sharedBuffer);
for (let i = 0; i < 1000; i++) {
  Atomics.add(view, 0, 1); // thread-safe increment
}
Shared memory requires Atomics for safe access. Without atomic operations, you get race conditions. For most use cases, message passing (postMessage) is safer and easier.

Worker Pool Pattern

Creating a worker per request is expensive. Use a pool:

import { Worker } from 'node:worker_threads';
import os from 'node:os';

class WorkerPool {
  constructor(workerPath, size = os.cpus().length) {
    this.workers = [];
    this.queue = [];
    for (let i = 0; i < size; i++) {
      this.addWorker(workerPath);
    }
  }

  addWorker(path) {
    const worker = new Worker(path);
    worker.busy = false;
    worker.on('message', (result) => {
      worker.busy = false;
      worker.resolve(result);
      this.processQueue();
    });
    this.workers.push(worker);
  }

  run(data) {
    return new Promise((resolve, reject) => {
      const idle = this.workers.find(w => !w.busy);
      if (idle) {
        idle.busy = true;
        idle.resolve = resolve;
        idle.postMessage(data);
      } else {
        this.queue.push({ data, resolve, reject });
      }
    });
  }

  processQueue() {
    if (this.queue.length === 0) return;
    const idle = this.workers.find(w => !w.busy);
    if (!idle) return;
    const { data, resolve } = this.queue.shift();
    idle.busy = true;
    idle.resolve = resolve;
    idle.postMessage(data);
  }
}

Production alternative: use the piscina package — a battle-tested worker pool.
