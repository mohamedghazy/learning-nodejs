Network Protocols — Lesson 02

TCP Deep Dive

Sockets, reliable delivery, and building a raw TCP server with node:net.

What Is a Socket?

A socket is an endpoint in a network connection — a combination of an IP address and a port number. Think of it as a phone number: IP is the building, port is the apartment inside it. 

192.168.1.10:3000
│             │
IP address    Port
(the machine) (the process/service)

A TCP connection is identified by a 4-tuple: (source IP, source port, dest IP, dest port). This is how your server can handle thousands of simultaneous connections — each has a unique 4-tuple.

Well-known ports: HTTP = 80, HTTPS = 443, SSH = 22, PostgreSQL = 5432, Redis = 6379. Ports below 1024 require root/admin on Linux. Your dev servers use 3000, 8080, etc. to avoid this.

The TCP Connection Lifecycle

A TCP connection goes through a defined sequence of states. Understanding this is essential for debugging ECONNREFUSED, ETIMEDOUT, and ECONNRESET errors. 

State           Who enters it     What's happening
─────────────────────────────────────────────────────────
LISTEN          Server            Waiting for incoming connections (after .listen())
SYN_SENT        Client            SYN sent, waiting for SYN-ACK
SYN_RECEIVED    Server            SYN received, SYN-ACK sent
ESTABLISHED     Both              Data can flow in both directions
FIN_WAIT_1      Closer            FIN sent, waiting for ACK
FIN_WAIT_2      Closer            Got ACK, waiting for peer's FIN
TIME_WAIT       Closer            Waiting to ensure remote ACK arrived (2× MSL)
CLOSE_WAIT      Receiver          Got FIN, waiting for app to close
LAST_ACK        Receiver          FIN sent, waiting for final ACK
CLOSED          Both              No connection
TIME_WAIT is why you get "address already in use". After closing a server, the port stays in TIME_WAIT for ~60 seconds. Fix: server.listen({ port, reuseAddress: true }) or use SO_REUSEADDR socket option. In production this is standard practice.

How TCP Guarantees Delivery

Sequence Numbers and Acknowledgements

Every byte sent over TCP has a sequence number. The receiver sends back an ACK containing the next expected sequence number. If the sender doesn't receive an ACK within a timeout, it retransmits. 

Sender                    Receiver
  |                           |
  |------ seq=100, data ----->|
  |------ seq=200, data ----->|    (pipelined, don't wait)
  |                           |
  |<------ ACK=300 -----------|    "I got everything up to 300"
  |                           |
  |------ seq=300, data ----->|
  |  (no ACK arrives...)      |
  |------ seq=300, data ----->|    Retransmit!

Flow Control — Slow Receiver Problem

What if the sender blasts data faster than the receiver can process it? TCP uses a receive window — the receiver advertises how much buffer space it has. The sender can't send more than that amount without an ACK.

Congestion Control — Network Overload Problem

What if the network itself is congested? TCP uses algorithms like slow start and congestion avoidance to probe the network capacity and back off when packets are dropped.

The key insight for a Node.js dev: All of this happens in the OS kernel, below your code. What you see is that socket.write() may return false when the write buffer is full (backpressure), and you should wait for the 'drain' event. This is the same backpressure mechanism you learned in the fs streams lessons.

TCP in Node.js — node:net

node:net gives you raw TCP access. A socket in Node.js is a Duplex stream — you can both read from it and write to it.

Building a TCP Server

import net from 'node:net';

const server = net.createServer((socket) => {
  // socket is a net.Socket — a Duplex stream
  console.log(`Connected: ${socket.remoteAddress}:${socket.remotePort}`);

  // Read incoming data (it's a stream — arrives in chunks)
  socket.on('data', (chunk) => {
    console.log(`Received: ${chunk.toString()}`);
    // Echo it back
    socket.write(chunk);
  });

  socket.on('end', () => {
    // Client closed their write side (sent FIN)
    console.log('Client disconnected');
  });

  socket.on('error', (err) => {
    // Handle ECONNRESET, ETIMEDOUT, etc.
    console.error('Socket error:', err.code);
  });
});

server.listen(8080, '127.0.0.1', () => {
  console.log('TCP server listening on 127.0.0.1:8080');
});

Building a TCP Client

import net from 'node:net';

const client = net.createConnection({ port: 8080, host: '127.0.0.1' }, () => {
  // Callback fires when 'connect' event happens (handshake complete)
  console.log('Connected to server');
  client.write('Hello from client\n');
});

client.on('data', (chunk) => {
  console.log(`Server says: ${chunk.toString()}`);
  client.end();  // Send FIN — close our write side
});

client.on('error', (err) => {
  // ECONNREFUSED if server isn't running
  console.error('Connection error:', err.code);
});

The Critical Problem: TCP Is a Byte Stream, Not a Message Stream

This is where most new Node.js network developers get caught. TCP does not know about your "messages". It delivers a continuous stream of bytes.

You send two messages: 

socket.write('Hello');
socket.write('World');

The receiver might see any of these: 

'HelloWorld'      // merged into one chunk
'Hel' + 'loWorld' // split arbitrarily
'Hello' + 'World' // what you expected, but NOT guaranteed

This is called TCP framing — you need to define where one message ends and the next begins. Common strategies:

StrategyHow it worksUsed by
Delimiter Append \n or \0 after each message Redis, SMTP, IRC
Length prefix Prefix each message with its byte length (e.g., 4-byte uint32) HTTP/2, gRPC, most binary protocols
Fixed size All messages are exactly N bytes Some sensor/hardware protocols
Self-describing Message format defines its own boundaries (e.g., JSON balanced braces) HTTP/1.1 via Content-Length or chunked encoding
This is why you can't naively read TCP data as strings. HTTP handles this with Content-Length headers and chunked transfer encoding. When building your own TCP protocol, always implement framing.

Practical: Newline-Delimited JSON over TCP

import net from 'node:net';

const server = net.createServer((socket) => {
  let buffer = '';

  socket.setEncoding('utf8');

  socket.on('data', (chunk) => {
    buffer += chunk;

    // Split on newlines to extract complete messages
    const lines = buffer.split('\n');

    // The last element may be an incomplete message — keep it
    buffer = lines.pop();

    for (const line of lines) {
      if (!line.trim()) continue;
      try {
        const msg = JSON.parse(line);
        // Process complete message
        socket.write(JSON.stringify({ ok: true, echo: msg }) + '\n');
      } catch {
        socket.write(JSON.stringify({ ok: false, error: 'Invalid JSON' }) + '\n');
      }
    }
  });
});

server.listen(8080);
