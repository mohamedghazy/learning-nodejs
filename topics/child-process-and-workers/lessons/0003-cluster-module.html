Processes — Lesson 03

The Cluster Module

One Node.js process per CPU core — the built-in way to scale your HTTP server.

The Problem Cluster Solves

A single Node.js process uses one CPU core. On an 8-core server, 87% of your CPU is idle. The cluster module forks your server multiple times — one worker per core — and distributes incoming connections across them. 

import cluster from 'node:cluster';
import http from 'node:http';
import os from 'node:os';

if (cluster.isPrimary) {
  // Primary process: fork workers
  const numCPUs = os.cpus().length;
  console.log(`Primary ${process.pid} forking ${numCPUs} workers`);

  for (let i = 0; i < numCPUs; i++) {
    cluster.fork();
  }

  cluster.on('exit', (worker, code) => {
    console.log(`Worker ${worker.process.pid} died (code: ${code})`);
    cluster.fork(); // Replace dead workers
  });
} else {
  // Worker process: run the server
  http.createServer((req, res) => {
    res.end(`Hello from worker ${process.pid}\n`);
  }).listen(3000);

  console.log(`Worker ${process.pid} started`);
}

All workers share the same port (3000). The OS distributes connections between them using a round-robin strategy (on most platforms).

When to Use Cluster vs Worker Threads

NeedSolutionWhy
Scale HTTP server across cores Cluster Multiple server processes sharing one port
CPU-heavy task in a request handler Worker Thread Don't block the event loop, stay in-process
Run ffmpeg/Python/shell Child Process External binary, separate process
Isolated microservice Separate process/container Full isolation, independent deployment

Graceful Shutdown

// In primary:
process.on('SIGTERM', () => {
  console.log('Shutting down...');
  for (const id in cluster.workers) {
    cluster.workers[id].send('shutdown');
  }
});

// In worker:
process.on('message', (msg) => {
  if (msg === 'shutdown') {
    server.close(() => {
      console.log(`Worker ${process.pid} closed gracefully`);
      process.exit(0);
    });
  }
});

In Production: Use PM2 or Docker

You rarely write cluster code manually in production. Instead:

  • PM2 — pm2 start server.js -i max (auto-clusters + monitoring + restarts)
  • Docker + orchestrator — run multiple containers, load balancer distributes
  • Serverless — each request gets its own instance (Vercel, AWS Lambda)
The practical answer: Understand cluster for interviews and debugging. In production, use PM2 or container orchestration — they handle worker management, restarts, logging, and zero-downtime deploys better than hand-written cluster code.
