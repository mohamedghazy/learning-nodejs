Network Protocols — Lesson 05

TLS — Encryption on the Wire

What happens between TCP and HTTP, how certificates work, and node:tls in practice.

The Problem TLS Solves

TCP delivers your bytes reliably. But TCP has no concept of confidentiality or authenticity. An attacker who can intercept your traffic (a coffee shop router, a compromised ISP, a man-in-the-middle) can read and modify everything in plain text.

TLS (Transport Layer Security) sits between TCP and HTTP: 

Application layer   HTTP / WebSocket / gRPC
                    ───────────────────────
Security layer      TLS / SSL  ← encrypts the data
                    ───────────────────────
Transport layer     TCP        ← delivers bytes reliably
                    ───────────────────────
Internet layer      IP         ← routes packets

TLS provides three guarantees:

  • Confidentiality — data is encrypted; interceptors see garbage
  • Integrity — data cannot be tampered with undetected (MAC/AEAD)
  • Authentication — you know you're talking to the real server (certificates)

The TLS Handshake

Before encrypted data flows, TLS negotiates keys. TLS 1.3 (current standard) does this in one round trip after the TCP handshake: 

TCP Handshake (1 round trip)
  Client ──SYN──────────────────→ Server
  Client ←──SYN-ACK────────────── Server
  Client ──ACK──────────────────→ Server

TLS 1.3 Handshake (1 more round trip)
  Client ──ClientHello──────────→ Server
         (supported cipher suites,
          key share for ECDHE,
          random nonce)

  Client ←──ServerHello────────── Server
         (chosen cipher suite,
          server key share,
          certificate,
          Finished — server is now authenticated)

  Client ──Finished─────────────→ Server
         (client is authenticated if mutual TLS)

Encrypted application data flows immediately after ↑
TLS 1.2 vs 1.3: TLS 1.2 (still common) requires 2 round trips. TLS 1.3 (current) requires 1 round trip and supports 0-RTT resumption for reconnecting clients. Always enforce TLS 1.2 minimum; prefer TLS 1.3 in new deployments.

How Certificates Work

A TLS certificate is a signed document that says: "I am api.example.com, and a trusted authority (CA) vouches for me."

The trust chain:

Root CA (e.g., Let's Encrypt ISRG Root X1)
  └── Intermediate CA (e.g., Let's Encrypt R3)
        └── Your certificate (api.example.com)

Your browser/Node.js has a built-in list of trusted Root CAs.
It walks the chain: can it trace to a trusted root? → Valid.

Each certificate contains:

  • Subject — the domain (or wildcard: *.example.com)
  • Issuer — which CA signed it
  • Valid from / until — expiry (typically 90 days for Let's Encrypt)
  • Public key — used in key exchange
  • Signature — CA's digital signature (verifies authenticity)
  • SANs — Subject Alternative Names (other domains this cert covers)

node:tls — Raw TLS in Node.js

Creating a TLS Server

import tls from 'node:tls';
import fs from 'node:fs';

const options = {
  key:  fs.readFileSync('./server.key'),   // Private key (keep secret!)
  cert: fs.readFileSync('./server.crt'),   // Certificate
  ca:   fs.readFileSync('./ca.crt'),       // CA cert (if using custom CA)

  // Enforce minimum TLS version
  minVersion: 'TLSv1.2',

  // Allowed cipher suites (explicit allowlist is safer than default)
  ciphers: 'ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384',
};

const server = tls.createServer(options, (socket) => {
  console.log('TLS version:', socket.getProtocol());
  console.log('Cipher:', socket.getCipher().name);

  socket.write('Hello over TLS!\n');
  socket.pipe(socket); // echo
});

server.listen(8443);

Creating a TLS Client

import tls from 'node:tls';

const socket = tls.connect({
  host: 'api.example.com',
  port: 443,
  // Node.js verifies the certificate by default.
  // rejectUnauthorized: false disables this — NEVER do this in production.
}, () => {
  console.log('Connected, authorized:', socket.authorized);
  socket.write('GET / HTTP/1.1\r\nHost: api.example.com\r\n\r\n');
});

socket.on('data', (data) => console.log(data.toString()));

HTTPS Is Just TLS + HTTP

node:https is simply node:http wrapped with node:tls. All the TLS options are passed straight through: 

import https from 'node:https';
import fs from 'node:fs';

const server = https.createServer({
  key:  fs.readFileSync('./server.key'),
  cert: fs.readFileSync('./server.crt'),
}, (req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({ secure: true }));
});

server.listen(443);
In production, you rarely terminate TLS in Node.js directly. Most production setups terminate TLS at a reverse proxy (Nginx, Caddy, AWS ALB) and proxy plain HTTP to your Node.js app. This is easier to manage (cert rotation, multiple instances, HTTP/2 support) and offloads the crypto work from Node.

Self-Signed Certificates for Development

For local HTTPS development, generate a self-signed cert: 

# Generate a private key and self-signed certificate
openssl req -x509 -newkey rsa:4096 -keyout server.key -out server.crt \
  -days 365 -nodes -subj '/CN=localhost'

# Or use mkcert for a locally-trusted cert (recommended)
# brew install mkcert && mkcert -install && mkcert localhost
Never disable certificate verification in production. rejectUnauthorized: false or NODE_TLS_REJECT_UNAUTHORIZED=0 defeats the entire point of TLS and opens you to man-in-the-middle attacks. For dev environments, use mkcert or add your CA to the trust store.

Mutual TLS (mTLS) — Both Sides Authenticate

Standard TLS authenticates the server to the client. Mutual TLS (mTLS) also authenticates the client to the server. The client presents its own certificate.

This is the standard for service-to-service communication in microservices (Istio, Linkerd use it). No passwords or tokens — identity is cryptographic. 

// Server: require client certificate
const server = tls.createServer({
  key:  fs.readFileSync('./server.key'),
  cert: fs.readFileSync('./server.crt'),
  ca:   fs.readFileSync('./client-ca.crt'),  // Trust this CA for clients
  requestCert: true,        // Request client cert
  rejectUnauthorized: true, // Reject if cert is invalid
}, (socket) => {
  if (!socket.authorized) {
    socket.destroy(new Error('Unauthorized client'));
    return;
  }
  // Client is authenticated
});
