Backend Concepts — Lesson 02

Middleware Deep Dive

The core abstraction of backend frameworks — how the middleware stack works, next(), and the request lifecycle.

What Is Middleware?

Middleware is a function that has access to the request object (req), the response object (res), and the next function. It can:

  • Execute any code
  • Modify req and res
  • End the request-response cycle
  • Call the next middleware in the stack
function myMiddleware(req, res, next) {
  // Do something with req/res
  console.log(`${req.method} ${req.path}`);
  
  // Then either:
  next();              // Pass control to the next middleware
  // OR
  res.send('Done');    // End the cycle (don't call next)
}

Here's the key insight: route handlers are also middleware. The only difference is that route handlers typically end the cycle instead of calling next().

This pattern exists across frameworks: Express, Koa, Fastify (via hooks), Hono, and even non-Node.js frameworks like Django (as "middleware") and Rails (as "middleware/filters").

The Middleware Stack

Frameworks process requests through a stack of middleware functions, in order:

const app = express();

// Middleware 1 (runs first)
app.use((req, res, next) => {
  console.log('Middleware 1');
  next();
});

// Middleware 2 (runs second)
app.use((req, res, next) => {
  console.log('Middleware 2');
  next();
});

// Route handler (runs third, ends cycle)
app.get('/', (req, res) => {
  console.log('Route handler');
  res.send('Hello');
});

// Request to GET / logs:
// Middleware 1
// Middleware 2
// Route handler

Visualize it as a pipeline:

Request → [Middleware 1] → [Middleware 2] → [Route Handler] → Response
               ↓                 ↓                  ↓
            next()            next()           res.send()

The next() Function

next() is how you pass control to the next middleware. Without it, the request hangs:

// ❌ BAD — request hangs forever
app.use((req, res, next) => {
  console.log('Logging...');
  // Forgot to call next() or send response!
});

// ✓ GOOD — passes control forward
app.use((req, res, next) => {
  console.log('Logging...');
  next();
});

next() Variants

// 1. next() — continue to next middleware
next();

// 2. next('route') — skip remaining handlers for this route, go to next route
app.get('/users/:id',
  (req, res, next) => {
    if (req.params.id === '0') {
      return next('route');  // Skip to next app.get()
    }
    next();
  },
  (req, res) => {
    res.send('User found');
  }
);
app.get('/users/:id', (req, res) => {
  res.send('Fallback route');  // Hit when id === '0'
});

// 3. next(error) — jump to error handling middleware
next(new Error('Something broke'));

Middleware Scope: Global vs Route-Specific

Global Middleware (app.use() without path)

// Runs for EVERY request
app.use((req, res, next) => {
  req.requestTime = Date.now();
  next();
});

Path-Specific Middleware

// Only runs for /api/* routes
app.use('/api', (req, res, next) => {
  console.log('API request');
  next();
});

// Only runs for this exact route
app.get('/admin', checkAuth, (req, res) => {
  res.send('Admin panel');
});

Router-Level Middleware

const router = Router();

// Applies to all routes in this router
router.use((req, res, next) => {
  console.log('Router middleware');
  next();
});

router.get('/', handler);
router.get('/:id', handler);

Order Matters — A Lot

Middleware executes in the order it's defined. This is critical:

// ❌ WRONG ORDER — body not parsed yet
app.post('/users', (req, res) => {
  console.log(req.body);  // undefined!
});
app.use(express.json());  // Too late

// ✓ CORRECT ORDER — parser runs first
app.use(express.json());  // Parse JSON bodies
app.post('/users', (req, res) => {
  console.log(req.body);  // { name: 'Mohamed' }
});

Typical middleware order:

const app = express();

// 1. Security middleware (CORS, helmet)
app.use(cors());
app.use(helmet());

// 2. Body parsers
app.use(express.json());
app.use(express.urlencoded({ extended: true }));

// 3. Logging
app.use(morgan('dev'));

// 4. Static files
app.use(express.static('public'));

// 5. Session/Auth
app.use(session({ ... }));
app.use(passport.initialize());

// 6. Your routes
app.use('/api', apiRouter);
app.use('/', viewRouter);

// 7. 404 handler (no route matched)
app.use((req, res) => {
  res.status(404).json({ error: 'Not found' });
});

// 8. Error handler (MUST be last, MUST have 4 params)
app.use((err, req, res, next) => {
  res.status(500).json({ error: err.message });
});

Types of Middleware

1. Application-Level Middleware

app.use(middlewareFunction);
app.get('/path', middlewareFunction, handler);

2. Router-Level Middleware

const router = Router();
router.use(middlewareFunction);

3. Built-in Middleware

// Parse JSON bodies
app.use(express.json());

// Parse URL-encoded bodies (form submissions)
app.use(express.urlencoded({ extended: true }));

// Serve static files
app.use(express.static('public'));

4. Third-Party Middleware

import cors from 'cors';
import helmet from 'helmet';
import morgan from 'morgan';

app.use(cors());           // CORS headers
app.use(helmet());         // Security headers
app.use(morgan('dev'));    // Request logging

5. Error-Handling Middleware

// MUST have exactly 4 parameters
app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(500).json({ error: 'Something broke!' });
});

Error Handling Middleware — The Special Case

Error middleware is different. It has 4 parameters instead of 3:

// Regular middleware: (req, res, next)
// Error middleware:   (err, req, res, next)

app.use((err, req, res, next) => {
  console.error('Error:', err.message);
  
  if (res.headersSent) {
    return next(err);  // Delegate to default handler
  }
  
  res.status(err.status || 500).json({
    error: err.message,
    ...(process.env.NODE_ENV === 'development' && { stack: err.stack })
  });
});

How errors reach the error handler:

// Method 1: Call next(error)
app.get('/users/:id', (req, res, next) => {
  const user = findUser(req.params.id);
  if (!user) {
    return next(new Error('User not found'));
  }
  res.json(user);
});

// Method 2: Throw (sync code only)
app.get('/sync', (req, res) => {
  throw new Error('Sync error');  // Express catches this
});

// Method 3: Async errors (Express 5+ or wrapper needed)
app.get('/async', async (req, res, next) => {
  try {
    const data = await fetchData();
    res.json(data);
  } catch (err) {
    next(err);  // Must manually pass async errors
  }
});
Express 4 async trap: In Express 4, thrown errors in async functions are NOT caught automatically. You must use try/catch and call next(err). Express 5 fixes this.

Async Error Wrapper (Express 4)

// Utility to catch async errors
const asyncHandler = (fn) => (req, res, next) => {
  Promise.resolve(fn(req, res, next)).catch(next);
};

// Usage — no try/catch needed
app.get('/users', asyncHandler(async (req, res) => {
  const users = await db.query('SELECT * FROM users');
  res.json(users);
  // If db.query throws, asyncHandler catches it and calls next(err)
}));

Modifying req and res

Middleware often attaches data to req for later middleware to use:

// Authentication middleware
async function authenticate(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];
  
  if (!token) {
    return res.status(401).json({ error: 'No token' });
  }
  
  try {
    const decoded = jwt.verify(token, SECRET);
    req.user = decoded;  // Attach user to request
    next();
  } catch {
    res.status(401).json({ error: 'Invalid token' });
  }
}

// Later middleware/routes can access req.user
app.get('/profile', authenticate, (req, res) => {
  res.json({ user: req.user });  // req.user exists because authenticate ran
});

Common patterns:

  • req.user — authenticated user
  • req.session — session data
  • req.body — parsed request body
  • req.files — uploaded files (multer)
  • res.locals — data for templates

Conditional Middleware

Run middleware only under certain conditions:

// Only parse JSON for specific content types
app.use((req, res, next) => {
  if (req.is('application/json')) {
    express.json()(req, res, next);
  } else {
    next();
  }
});

// Skip middleware for certain paths
const unlessPath = (paths, middleware) => {
  return (req, res, next) => {
    if (paths.includes(req.path)) {
      return next();
    }
    middleware(req, res, next);
  };
};

app.use(unlessPath(['/login', '/register'], authenticate));

Writing Reusable Middleware

Middleware factories return middleware functions with configuration:

// Middleware factory
function rateLimit(options = {}) {
  const { windowMs = 60000, max = 100 } = options;
  const requests = new Map();

  return (req, res, next) => {
    const ip = req.ip;
    const now = Date.now();
    const windowStart = now - windowMs;

    // Clean old entries
    const requestTimes = (requests.get(ip) || [])
      .filter(time => time > windowStart);

    if (requestTimes.length >= max) {
      return res.status(429).json({ error: 'Too many requests' });
    }

    requestTimes.push(now);
    requests.set(ip, requestTimes);
    next();
  };
}

// Usage
app.use(rateLimit({ windowMs: 60000, max: 100 }));  // 100 req/min
app.use('/api', rateLimit({ max: 30 }));             // 30 req/min for /api

The Request Lifecycle — Complete Picture

Incoming Request
      ↓
┌─────────────────────────────────────────────┐
│  Global Middleware (app.use without path)   │
│  - CORS, Helmet, Body parsers, Logging      │
└─────────────────────────────────────────────┘
      ↓
┌─────────────────────────────────────────────┐
│  Path-Specific Middleware                   │
│  - app.use('/api', apiMiddleware)           │
└─────────────────────────────────────────────┘
      ↓
┌─────────────────────────────────────────────┐
│  Route Matching                             │
│  - First matching route wins                │
└─────────────────────────────────────────────┘
      ↓
┌─────────────────────────────────────────────┐
│  Route Handlers (also middleware)           │
│  - app.get('/users', handler1, handler2)    │
└─────────────────────────────────────────────┘
      ↓
┌─────────────────────────────────────────────┐
│  If no route matched: 404 handler           │
│  If error thrown: Error middleware          │
└─────────────────────────────────────────────┘
      ↓
   Response Sent
