Processes — Lesson 04

Decision Guide — When to Use What

A clear mental model for choosing between event loop, Worker Threads, child processes, and cluster.

The Decision Flowchart

Is the task I/O-bound (network, disk, database)?
  YES → Use async/await + event loop (default Node.js)
         No threads needed. This handles 99% of web server work.

Is it CPU-bound (computation, parsing, crypto)?
  Is it JavaScript/WASM code?
    YES → Worker Threads
           Shared memory, low overhead, stays in-process
  Is it an external program (ffmpeg, Python, shell)?
    YES → Child Process (spawn/exec)
           Separate binary, streams or buffered output

Do you need to scale HTTP across all CPU cores?
  YES → Cluster (or PM2/Docker)
         Multiple server instances sharing one port

Real-World Scenarios

ScenarioSolutionWhy
Handling 10K concurrent API requests Event loop (async/await) I/O-bound — event loop handles this natively
Hash a password with bcrypt Worker Thread (or built-in async bcrypt) CPU-bound, ~100ms computation
Convert uploaded video to MP4 Child Process (spawn ffmpeg) External binary, large streaming output
Parse a 100MB CSV file Streams (event loop) OR Worker Thread Streams if I/O-bound; worker if CPU-bound parsing
Generate PDF reports Worker Thread (or child process) CPU-bound rendering, ~200ms per PDF
Run npm install from your app Child Process (exec/spawn) Shell command, external process
Serve 50K requests/sec on 8 cores Cluster (PM2) or containers Scale HTTP horizontally across cores
Real-time image resize on upload Worker Thread + sharp library CPU-bound image processing in JS/native
Run database queries Event loop (async/await) I/O-bound — network wait, not CPU
Machine learning inference Worker Thread or Child Process CPU-heavy, depends on runtime (JS vs Python)

Common Mistakes

MistakeProblemFix
Using Worker Thread for a database query Pointless — DB queries are I/O-bound, not CPU Just use await db.query()
Spawning a new worker per request Worker creation is ~5ms — adds up under load Use a worker pool (piscina)
Using cluster for a single CPU-heavy endpoint Cluster scales the entire server, not one task Use Worker Thread for the specific task
exec(userInput) for shell commands Command injection vulnerability Use spawn with args array
