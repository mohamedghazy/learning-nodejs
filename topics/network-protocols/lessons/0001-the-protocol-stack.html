Network Protocols — Lesson 01

The Protocol Stack

What lives below HTTP — and why a Node.js backend dev needs to care.

You've Already Been Using This Stack

Every fetch('/api/users') you've ever written travels through four layers before it reaches your Node.js server. HTTP is just the top layer. Below it:

LayerProtocolWhat it doesYour abstraction
Application HTTP, WebSocket, DNS Defines message format and semantics fetch(), node:http
Transport TCP, UDP Delivers data between processes node:net, node:dgram
Internet IP (IPv4/IPv6) Routes packets between machines IP addresses in your server config
Link Ethernet, Wi-Fi Physically moves bits between devices Your NIC — you never touch this
The model used here is TCP/IP (not OSI). The OSI model has 7 layers and is more common in textbooks. TCP/IP has 4 layers and is what the internet actually runs on. Cloudflare: OSI vs TCP/IP

Why HTTP Alone Isn't Enough

HTTP is a protocol built on top of TCP. HTTP says "GET /users HTTP/1.1" — but it has no idea how those bytes get from your browser to the server. That's TCP's job.

HTTP doesn't handle:

  • How to establish a connection between two machines
  • What to do when a packet is lost in transit
  • How to handle data arriving out of order
  • How to avoid flooding a slow receiver

TCP handles all of that. HTTP just rides on top.

The Two Transport Protocols You Need to Know

TCP — Transmission Control Protocol

TCP is a connection-oriented, reliable, ordered protocol. Before data can flow, both ends perform a handshake. Every byte sent is acknowledged. Lost packets are retransmitted. Data arrives in the exact order it was sent.

Used by: HTTP, HTTPS, WebSocket, SSH, FTP, SMTP, databases (Postgres, MySQL, MongoDB). Basically: everything where data correctness matters.

UDP — User Datagram Protocol

UDP is connectionless, unreliable, unordered. You fire a packet and forget it. No handshake. No acknowledgement. Packets can arrive out of order, be duplicated, or never arrive at all.

Used by: DNS queries, video streaming, online gaming, VoIP, WebRTC data channels. Basically: everything where speed beats correctness, or where the application handles its own reliability.

A common misconception: "UDP is unreliable" doesn't mean it's broken — it means the protocol itself doesn't guarantee delivery. Your application can build reliability on top (QUIC, which powers HTTP/3, does exactly this).

The TCP Three-Way Handshake

Before a single byte of HTTP data flows, TCP establishes a connection using three messages: 

Client                Server
  |                     |
  |------- SYN -------->|   "I want to connect. My sequence starts at X."
  |                     |
  |<------ SYN-ACK -----|   "OK. Yours starts at X+1. Mine starts at Y."
  |                     |
  |------- ACK -------->|   "Got it. Your sequence starts at Y+1."
  |                     |
  |===== data flows =====|

This is why opening a TCP connection has latency. HTTPS adds another round trip for TLS. HTTP/2 and HTTP/3 reduce this overhead, but the TCP handshake is always there (unless you're on QUIC/UDP).

SYN / ACK are TCP flags — bits in the TCP header that indicate the purpose of the segment. SYN = synchronize (start connection). ACK = acknowledge (confirm receipt). FIN = finish (close connection).

Where Node.js Fits In

Node.js exposes the transport layer through two core modules: 

// TCP — node:net
import net from 'node:net';

const server = net.createServer((socket) => {
  socket.on('data', (chunk) => console.log(chunk));
  socket.write('hello\n');
});
server.listen(8080);

// UDP — node:dgram
import dgram from 'node:dgram';

const socket = dgram.createSocket('udp4');
socket.on('message', (msg, rinfo) => {
  console.log(`From ${rinfo.address}:${rinfo.port} — ${msg}`);
});
socket.bind(41234);

node:http is built on top of node:net internally. When you call http.createServer(), Node creates a TCP server under the hood.
