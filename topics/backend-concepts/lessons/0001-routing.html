Backend Concepts — Lesson 01

Routing Deep Dive

How web frameworks match URLs to handlers — route parameters, patterns, precedence, and modular routers.

What Is Routing?

Routing is the mechanism that determines which code handles a given HTTP request. It's the answer to: "When a request for GET /users/42 arrives, what function should run?"

In raw node:http, you did this manually:

if (req.method === 'GET' && req.url.startsWith('/users/')) {
  const id = req.url.split('/')[2];
  // handle it
}

Frameworks like Express replace this with a declarative routing API:

app.get('/users/:id', (req, res) => {
  const id = req.params.id;
  // handle it
});

But there's much more depth here than it appears. These concepts apply to Express, Fastify, Koa, Hono, and most other Node.js frameworks.

Route Definition Anatomy

app.METHOD(PATH, HANDLER)
Component What it is Example
app Framework application instance const app = express()
METHOD HTTP method (lowercase) get, post, put, patch, delete, all
PATH URL pattern to match '/users', '/users/:id', /^\/api\//
HANDLER Function(s) to execute (req, res) => {} or [fn1, fn2]

HTTP Method Matching

Each HTTP method has its own route method:

app.get('/resource', handler);     // GET requests only
app.post('/resource', handler);    // POST requests only
app.put('/resource', handler);     // PUT requests only
app.patch('/resource', handler);   // PATCH requests only
app.delete('/resource', handler);  // DELETE requests only

// Match ANY HTTP method
app.all('/resource', handler);     // GET, POST, PUT, DELETE, PATCH, OPTIONS, HEAD...

app.all() is useful for middleware that should run for all methods on a path:

// Log every request to /api/* regardless of method
app.all('/api/*', (req, res, next) => {
  console.log(`${req.method} ${req.path}`);
  next();
});

Route Parameters (Dynamic Segments)

Route parameters capture dynamic parts of the URL:

// :id is a route parameter
app.get('/users/:id', (req, res) => {
  console.log(req.params);  // { id: '42' }
  res.json({ userId: req.params.id });
});

// Multiple parameters
app.get('/users/:userId/posts/:postId', (req, res) => {
  console.log(req.params);  // { userId: '42', postId: '7' }
});

// Parameters are ALWAYS strings
app.get('/users/:id', (req, res) => {
  const id = req.params.id;          // '42' (string)
  const numId = Number(req.params.id); // 42 (number)
});
Important: Route parameters are always strings. If you need a number, parse it explicitly. '/users/42' → req.params.id === '42' (not 42).

Parameter Constraints with Regex

You can constrain what a parameter matches using regex in parentheses:

// Only match if :id is digits
app.get('/users/:id(\\d+)', (req, res) => {
  // /users/42 ✓ matches
  // /users/abc ✗ does NOT match (falls through)
  res.json({ id: req.params.id });
});

// Only match UUIDs
app.get('/items/:uuid([0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12})', handler);

Query Strings

Query strings (?key=value) are NOT part of the route pattern. They're parsed into req.query:

// Route: /search
// URL:   /search?q=express&limit=10&page=2

app.get('/search', (req, res) => {
  console.log(req.query);
  // { q: 'express', limit: '10', page: '2' }

  // All values are strings — parse as needed
  const limit = parseInt(req.query.limit, 10) || 20;
  const page = parseInt(req.query.page, 10) || 1;

  res.json({ query: req.query.q, limit, page });
});

Key difference from route params:

  • Route params (:id) — part of the URL structure, required for route to match
  • Query strings (?key=val) — optional metadata, always available on req.query

Route Patterns

Most frameworks support several pattern types beyond simple strings:

1. Exact Match

app.get('/about', handler);  // Only /about

2. Route Parameters

app.get('/users/:id', handler);  // /users/anything

3. Optional Parameters

app.get('/users/:id?', handler);  // /users OR /users/42

4. Wildcard (*)

// Match anything starting with /api/
app.get('/api/*', handler);  // /api/users, /api/posts/42, etc.

// Capture the wildcard part
app.get('/files/*', (req, res) => {
  // req.params[0] contains everything after /files/
  // /files/images/logo.png → req.params[0] === 'images/logo.png'
});

5. Regular Expressions

// Match any route containing 'fly'
app.get(/fly/, handler);  // /butterfly, /dragonfly, /fly

// Match routes ending in 'fly'
app.get(/.*fly$/, handler);  // /butterfly, /dragonfly (not /flying)

Route Precedence (Order Matters)

Most frameworks match routes in the order they're defined. First match wins:

// ❌ WRONG ORDER — /users/new never matches
app.get('/users/:id', (req, res) => {
  res.send(`User ${req.params.id}`);
});
app.get('/users/new', (req, res) => {
  res.send('Create user form');  // Never reached! 'new' matches :id
});

// ✓ CORRECT ORDER — specific routes first
app.get('/users/new', (req, res) => {
  res.send('Create user form');  // /users/new matches here
});
app.get('/users/:id', (req, res) => {
  res.send(`User ${req.params.id}`);  // /users/42 matches here
});
Rule of thumb: Define specific routes before parameterized routes. /users/new before /users/:id. Otherwise 'new' gets captured as an :id.

Multiple Handlers per Route

A route can have multiple handler functions. They execute in order:

// Method 1: Multiple arguments
app.get('/users/:id',
  validateId,
  loadUser,
  sendUser
);

// Method 2: Array of handlers
app.get('/users/:id', [validateId, loadUser, sendUser]);

// Each handler must call next() to continue to the next one
function validateId(req, res, next) {
  if (!/^\d+$/.test(req.params.id)) {
    return res.status(400).json({ error: 'Invalid ID' });
  }
  next();  // Continue to loadUser
}

function loadUser(req, res, next) {
  req.user = { id: req.params.id, name: 'Mohamed' };  // Attach to req
  next();  // Continue to sendUser
}

function sendUser(req, res) {
  res.json(req.user);  // No next() — this is the final handler
}

This is actually middleware in action — more on that in Lesson 2: Middleware.

Modular Routing (Express Router)

As your app grows, putting all routes in one file becomes unwieldy. express.Router() lets you create modular route handlers:

// routes/users.js
import { Router } from 'express';

const router = Router();

router.get('/', (req, res) => {
  res.json({ users: [] });
});

router.get('/:id', (req, res) => {
  res.json({ userId: req.params.id });
});

router.post('/', (req, res) => {
  res.status(201).json({ created: true });
});

export default router;
// app.js
import express from 'express';
import usersRouter from './routes/users.js';
import postsRouter from './routes/posts.js';

const app = express();

// Mount routers at path prefixes
app.use('/users', usersRouter);  // /users, /users/:id
app.use('/posts', postsRouter);  // /posts, /posts/:id

app.listen(3000);

The router's internal routes are relative to where it's mounted:

  • router.get('/') mounted at /users → handles GET /users
  • router.get('/:id') mounted at /users → handles GET /users/42

Nested Routers

// routes/users.js
import { Router } from 'express';
import postsRouter from './userPosts.js';

const router = Router();

router.get('/:id', getUser);
router.use('/:userId/posts', postsRouter);  // Nested!

export default router;

// routes/userPosts.js — handles /users/:userId/posts/*
const router = Router({ mergeParams: true });  // Access parent's :userId

router.get('/', (req, res) => {
  // req.params.userId available because of mergeParams
  res.json({ userId: req.params.userId, posts: [] });
});

export default router;
mergeParams: true — Essential for nested routers. Without it, the child router can't access route parameters defined in the parent (:userId).

Route Chaining

When you have multiple methods for the same path, chain them:

// Instead of:
app.get('/users', getUsers);
app.post('/users', createUser);
app.delete('/users', deleteAllUsers);

// Use route chaining:
app.route('/users')
  .get(getUsers)
  .post(createUser)
  .delete(deleteAllUsers);

app.route('/users/:id')
  .get(getUser)
  .put(updateUser)
  .delete(deleteUser);

Same functionality, cleaner code, and no risk of typos in repeated paths.

The 404 Catch-All

If no route matches, the framework sends a default 404. To customize it, add a catch-all at the end:

// All your routes first...
app.get('/', homeHandler);
app.use('/users', usersRouter);
app.use('/posts', postsRouter);

// Then the 404 catch-all (no path = matches everything)
app.use((req, res) => {
  res.status(404).json({
    error: 'Not Found',
    path: req.path,
    method: req.method
  });
});

This must be last. Routes are checked in order — if this came first, nothing else would ever match.
