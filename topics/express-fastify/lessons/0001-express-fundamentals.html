Express/Fastify — Lesson 01

Express Fundamentals

What Express actually does — and how it sits on top of node:http you already know.

The Problem Express Solves

You already built HTTP servers with the raw node:http module in HTTP Lesson 2. It works, but gets painful fast:

import http from 'node:http';

http.createServer(async (req, res) => {
  // Manual routing with if/else chains
  if (req.method === 'GET' && req.url === '/users') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ users: [] }));
  } else if (req.method === 'POST' && req.url === '/users') {
    // Manually collect body chunks
    const chunks = [];
    for await (const chunk of req) chunks.push(chunk);
    const body = JSON.parse(Buffer.concat(chunks).toString());
    // ... create user ...
  } else if (req.method === 'GET' && req.url.startsWith('/users/')) {
    // Manually parse URL params
    const id = req.url.split('/')[2];
    // ... find user ...
  } else {
    res.writeHead(404);
    res.end('Not found');
  }
}).listen(3000);

Problems with raw node:http:

  • Routing — manual if/else chains, manual URL parsing
  • Body parsing — collect chunks yourself every time
  • Response helpers — no res.json(), no res.redirect()
  • Cross-cutting concerns — logging, auth, CORS for every route? Copy-paste.

Express solves all of these with a thin abstraction layer.

Express Is node:http + Conveniences

Here's the key insight: Express does not replace node:http. It wraps it.

import express from 'express';

const app = express();

// This is still node:http underneath
app.listen(3000);

When you call app.listen(3000), Express internally does this:

// Inside Express (simplified)
import http from 'node:http';

const server = http.createServer(app); // app IS the request handler
server.listen(3000);

The app function Express gives you is literally the request handler function — the (req, res) => {} you passed to createServer() in HTTP Lesson 2. Express just enhanced req and res with extra methods.

Mental model: Express = node:http + routing + middleware + enhanced req/res. Everything you learned about HTTP still applies. Express just makes it less tedious.

The Express Application

import express from 'express';

const app = express();

// Define routes
app.get('/', (req, res) => {
  res.send('Hello World');
});

app.get('/users', (req, res) => {
  res.json({ users: [] });
});

app.post('/users', (req, res) => {
  res.status(201).json({ created: true });
});

// Start listening
app.listen(3000, () => {
  console.log('Server running on port 3000');
});

Key differences from raw node:http:

node:http Express
if (req.method === 'GET' && req.url === '/users') app.get('/users', handler)
res.writeHead(200, {...}); res.end(JSON.stringify(data)) res.json(data)
res.writeHead(201); res.end() res.status(201).send()
Manual chunk collection for body express.json() middleware → req.body

Enhanced Request Object

Express adds properties to req (still the same IncomingMessage stream underneath):

app.get('/users/:id', (req, res) => {
  // Everything from node:http still works
  console.log(req.method);         // 'GET'
  console.log(req.url);            // '/users/42?active=true'
  console.log(req.headers);        // { host: '...', ... }

  // Express additions
  console.log(req.params);         // { id: '42' } — route params
  console.log(req.query);          // { active: 'true' } — query string parsed
  console.log(req.path);           // '/users/42' — path without query
  console.log(req.body);           // Parsed body (if middleware used)

  res.json({ userId: req.params.id });
});

No more manual req.url.split('/') or new URL(req.url, base).searchParams.

Enhanced Response Object

Express adds convenience methods to res (still ServerResponse stream underneath):

app.get('/demo', (req, res) => {
  // res.json() — sets Content-Type and stringifies
  res.json({ message: 'hello' });

  // res.status() — chainable status setter
  res.status(201).json({ created: true });

  // res.send() — smart body sender (detects strings, objects, Buffers)
  res.send('plain text');        // Content-Type: text/html
  res.send({ obj: true });       // Content-Type: application/json
  res.send(Buffer.from('...')); // Content-Type: application/octet-stream

  // res.redirect() — redirect helper
  res.redirect('/new-location');           // 302 by default
  res.redirect(301, '/permanent-location'); // 301 permanent

  // res.sendFile() — send a file
  res.sendFile('/absolute/path/to/file.pdf');

  // res.set() — set headers
  res.set('X-Custom-Header', 'value');

  // Original node:http methods still work
  res.writeHead(200, { 'Content-Type': 'text/plain' });
  res.end('raw response');
});

What Express Does NOT Do

Express is intentionally minimal. It does not include:

  • Body parsing — you add express.json() middleware
  • Sessions — you add express-session
  • Authentication — you add passport or similar
  • Database ORM — you add sequelize, prisma, etc.
  • Validation — you add joi, zod, express-validator

This "batteries not included" philosophy means you compose exactly what you need. The tradeoff: more setup than full-stack frameworks like Nest.js or AdonisJS.

First Express Server — Your Turn

Create express-demo.js:

import express from 'express';

const app = express();

// GET / — returns { status: 'ok', timestamp: ... }
app.get('/', (req, res) => {
  res.json({ status: 'ok', timestamp: new Date().toISOString() });
});

// GET /greet?name=Mohamed — returns { greeting: 'Hello, Mohamed!' }
app.get('/greet', (req, res) => {
  const name = req.query.name || 'stranger';
  res.json({ greeting: `Hello, ${name}!` });
});

// GET /users/:id — returns { userId: '42' }
app.get('/users/:id', (req, res) => {
  res.json({ userId: req.params.id });
});

app.listen(3000, () => console.log('Express server on http://localhost:3000'));

Run: node express-demo.js

Test with:

curl http://localhost:3000/
curl http://localhost:3000/greet?name=Mohamed
curl http://localhost:3000/users/42
